# NDT Lab — заметки для Claude

Программа для лаборатории неразрушающего контроля: справочники (сотрудники, оборудование, техкарты,
нормативные документы, сварщики...) и заключения (РК и др.) с выдачей в PDF.
Плюс сервер синхронизации в `server/`.

## Правила работы (от владельца проекта)

- Отвечать **всегда по-русски**.
- **Перед каждым коммитом показать текст коммита и ждать подтверждения.**
- Коммиты раздельные по смыслу; каждый коммит должен собираться.
- `resources/data.lnkdb` (рабочая база) **не коммитить**, пока об этом прямо не попросят.
- Push владелец делает сам.
- Когда просят «объяснить» или «показать по шагам» — сначала план и код в чате, правки только после «делай».

## Программа (Windows, `engine/`)

- C++20, Dear ImGui 1.92, SDL3, SQLite (`external/sqlite`), PoDoFo, vcpkg. Сборка: `cmake --build build`
  (MSBuild, Debug → `build/Debug/NDTLab.exe`). Если exe запущен — линковка падает с LNK1168.
- `laboratory.*` — модель (все справочники и `reportsList`), `LoadDB`/`SaveDB`.
- `databaseManager.*` — SQLite: `Ensure*Table` (CREATE IF NOT EXISTS + ALTER ADD COLUMN), upsert `ON CONFLICT(id)`.
- `report.*` — заключение, дефекты РК (`DefectRt`), замеры (`FilmMeasurement`), участки/снимки/экспозиции.
- `appWindows/` — окна ImGui; `reportBuilder.cpp` — PDF.

Соглашения:
- Записи наследуют `NDT::DbRecord`: `id` (UUID v7), `updatedAt`, `deletedAt` (мягкое удаление).
  Любая правка — `NDT::MarkUpdated`, удаление — `NDT::MarkDeleted`, иначе запись не сохранится.
- В базу пишутся только изменённые записи: `updatedAt >= syncedAt` (`DatabaseManager::IsChanged`). Время — секунды UTC.
- Замеры и дефекты — часть заключения: их правка помечает изменённым заключение, пишутся в его транзакции.
- Прикреплённые файлы — `NDT::AttachedFile`, таблица `files`, содержимое под одним id не меняется.
- Перечисления: `enum class X : uint8_t {..., Count}` + `GetXStr`/`ParseX`, в базе — строки.
- Пути из строк приложения — только `NDT::PathFromUtf8`/`NDT::PathToUtf8` (иначе ломается кириллица в путях).
- Несохранённое помечается точкой (`UnsavedDocument`), сохранение — Ctrl+S.

## Сервер синхронизации (`server/`, подробности — `server/README.md`)

- C++20, cpp-httplib, libpqxx, nlohmann/json, PostgreSQL 16. VPS с Ubuntu 24.04, хост `ndtlab`
  в `~/.ssh/config`, пользователь `ndt` (вход только по ключу). Служба `ndtsync` слушает `127.0.0.1:8080`,
  снаружи — через SSH-туннель; HTTPS через nginx будет, когда появится домен.
- Записи хранятся документами JSON (`records`: tbl, id, rev, updated_at, deleted_at, device_id, data).
  Заключение — один документ с массивами `measurements` и `defects`.
- `POST /sync/push`, `GET /sync/pull?since=N`, `PUT/GET /files/{id}`, доступ по токену компьютера.
  Конфликт: остаётся последняя правка, затёртая версия — в `overwritten`.
- Выкладка только закоммиченного: `.\server\deploy\deploy.ps1` (Windows) или `./server/deploy/deploy.sh` (Linux).
  Собирается на самом сервере — файл, собранный на Arch, на Ubuntu не запустится.

## Где остановились

Сервер готов. Следующий шаг — **синхронизация в программе** (сначала показать план):
перевод записей в JSON и обратно, таблица `sync_state` (последний полученный rev, время синхронизации,
отметка «отправлено на сервер» отдельно от «сохранено на диск», `base_rev` у записей),
отправка/получение (кнопка или автоматически), запись с сервера при открытом окне редактирования.

Отложено: нормы допустимости дефектов (скользящее окно 300 мм), автовысота ячеек PDF,
не грузить удалённые заключения, домен + HTTPS.
