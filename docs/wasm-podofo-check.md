# Проверка PoDoFo под WebAssembly

Проверено 31 октября 2026 года: **PoDoFo 1.1.1 собирается под wasm32 и создаёт PDF непосредственно в браузере**.
Дополнительных правок исходников PoDoFo и её зависимостей не потребовалось: использованы стандартные порты и патчи vcpkg.

## Окружение и конфигурация

- Emscripten 6.0.13-git (`e13ee988ce3d87a738dd8f3661d02223308c412a`).
- vcpkg: `40f3c709db80acf154ac4b17a1f83c564ebd022e`.
- Проверка выполнения: Node.js 26.12.1 и Firefox 159.0, Linux x86-64.
- Целевая платформа: wasm32, статические библиотеки, Release, без потоков.
- C/C++ и линковка: `-fwasm-exceptions`; тестовый код: C++23, включая `std::format`.
- Пакет: `podofo[core]`, без Fontconfig и поиска системных шрифтов.
- Четыре шрифта NotoSans взяты непосредственно из `resources/fonts/*.cpp` текущего приложения.

## Проверки выполнения

Один и тот же WASM-модуль успешно выполнен в Node.js и настоящем Firefox через локальный HTTP-сервер:

1. Созданы две страницы A4 в альбомной ориентации.
2. Использованы четыре встроенных начертания NotoSans: Regular, Bold, Italic, BoldItalic.
3. Выведены кириллица, символы `№`, `Ø`, `×`, таблица с рамками и многострочным текстом.
4. Загружены и нарисованы PNG, JPEG и TIFF с ZIP-сжатием.
5. Записаны XMP-метаданные через libxml2.
6. PDF сохранён в виртуальную файловую систему и повторно прочитан PoDoFo; обе страницы сохранены.
7. Создана копия с шифрованием AES-256 (`AESV3R6`) и успешно прочитана с паролем.
8. Ошибка чтения некорректного PDF перехвачена как C++-исключение `PdfError`.

Независимая проверка Poppler (`pdfinfo`, `pdffonts`, `pdftotext`) подтвердила две страницы,
встраивание всех четырёх шрифтов с Unicode, сохранность кириллицы и совпадение текста обычного
и зашифрованного PDF. Первая страница также отрендерена и проверена визуально.

## Результаты и расположение файлов

Проверка изолирована в `build/wasm-podofo-check/` и исключена из Git существующим правилом `build/`.
Настольная сборка, рабочая база и исходники приложения не изменялись в рамках этой проверки.

- `install.log` — журнал сборки зависимостей; успешное завершение за 4,9 минуты.
- `triplets/wasm32-ndt.cmake` — настройки целевой платформы.
- `probe-src/` — CMake, C++-тест, Node.js и браузерный запуск, тестовые изображения.
- `probe-configure.log`, `probe-build.log` — конфигурация и линковка исполняемого теста.
- `node.log` — результаты Node.js.
- `browser-output/result.json` — результаты Firefox.
- `browser-output/podofo-wasm.pdf` — PDF, созданный в Firefox: 38 471 байт.
- `browser-output/podofo-wasm-encrypted.pdf` — AES-256, пароль `wasm-test`: 39 874 байта.

## Повторный запуск собранного теста

Из корня репозитория:

```sh
node build/wasm-podofo-check/probe-src/run-node.cjs \
  build/wasm-podofo-check/wasm-build \
  build/wasm-podofo-check/node-output

python3 build/wasm-podofo-check/probe-src/run-browser.py \
  build/wasm-podofo-check/wasm-build \
  build/wasm-podofo-check/browser-output
```

Исходники проверки и скомпилированные файлы находятся внутри `build/`: очистка этого каталога удалит их.

## Что это означает для NDT Lab

Перенос PDF-генерации на сервер ради совместимости с WASM не требуется: проверенные операции работают локально в браузере.
Подход с `GetOrCreateFontFromBuffer`, который используется в `LoadEmbeddedPDFFonts`, подходит для этой конфигурации.

Проверка не является сборкой всего NDT Lab или запуском настоящего `ReportBuilder`:
использован отдельный тест тех же операций PoDoFo и тех же шрифтов. При интеграции остаются
браузерное скачивание PDF, выбор и открытие вложений, хранение базы, SDL и общая конфигурация CMake.
Многопоточность, подпись PDF, поиск системных шрифтов и другие браузеры этой проверкой не покрыты.
